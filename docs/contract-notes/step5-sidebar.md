### Which provider and model wrote each comment (the user's requirement)

- **The label.** `SidebarSourceLabel`: the `cpu` symbol, "{provider} · {model}" in `Theme.metadataFont`, secondary, one line cut in the middle, tooltip "Written by {providerID}, model {model id}" ("model not named (the provider's default)" without one), VoiceOver "Written by {provider}, model {model}". On every AI comment: full and compact cards (in the header's facts), the folded similar card (after the title, or on its first line with the badge when the title is long), the rejected line (beside the title), and the drafts of a running review. The referee's own comments show none.
- **The folded similar card** also names the other comment's source: "Similar to: {title} ({provider} · {model})", the title cut first.
- **Answers** in discussions and in the Chat tab carry the label under the bubble, from `ThreadMessage.provider`; questions and answers without a recorded provider carry none; the answer being streamed has none until it is finished.
- **The derivation** (`SidebarSource.swift`, pure, `SidebarSourceTests`): the comment's run (`session.runs`, by `runID`) gives a `ProviderRef`. Provider name: a descriptor the window has (`selectableProviders`, active, chat and report providers) without its bracketed plan for a CLI or a local provider ("Claude Code (subscription)" → "Claude Code", "Ollama (local)" → "Ollama"; stand-ins keep "Mock (remote)"), else `SidebarSourceNames.knownProviders` (the nine providers of §5.2), else the id. Model: the display name from `settings.providers[id].cachedModels` when it differs from the id, else the id; nil reads "default model". A comment of the review still running (its run is recorded only when it ends) takes the active provider and model; an AI comment whose run the session does not have reads "Model not recorded".
- **For the integrator's next step** (the model a provider reports it used): `SidebarSource.reportedModel` exists and, when set, wins over the requested model in the text and the tooltip; filling it is one line in `SidebarSourceNames.source(of:)` once `RunRecord` or `ThreadMessage` carries the reported model.

## Contract problems

1. **No public descriptor for a provider that is switched off.** `ReviewSessionModel` exposes `selectableProviders` (enabled, and not hidden by Local only), `activeProvider`, `chatProvider` and `reportProvider`; a comment written by a provider switched off since has no descriptor to name it by. *Workaround:* `SidebarSourceNames.knownProviders`, the nine providers of §5.2 with their short names; a test checks it against the snapshot registry's descriptors (which `IntegrationTests` compares with the real adapters) and against `DefaultSettings`' ids; any other id shows as itself. *Suggested:* `public var registeredProviders: [ProviderDescriptor]` (or `descriptor(for:)`) on `ReviewSessionModel`, and `knownProviders` goes.
2. **The running review's run is not in the session.** The model appends a `RunRecord` when the run ends; the record of `.started` is private. The comments a review has delivered so far point to a run the session does not have. *Workaround:* they take `activeProvider` and `activeModel`, which are what the review asked for unless the referee changes the provider during the run (then the label is wrong until the run ends). *Suggested:* append the run at `.started` (status `.running`), or expose the running run's `ProviderRef`.
3. **The model a provider reports is not recorded.** `RunRecord.provider.model` and `ThreadMessage.provider.model` are the requested model, nil for a CLI's default, so the label reads "default model". The integrator's next step; `SidebarSource.reportedModel` is ready for it.

None of these needed a file outside the Sidebar's paths.
