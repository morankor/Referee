## The flaky test

`LLMKitCancellationTests.cancellingTheConsumerCancelsTheRequestAndEndsTheStream` (it waits up to 8 s for the first two deltas of a slow stub stream) passed in the full run after the merge (load 18) and in the run made for it with no other build going (load 19–25, nothing compiling): `test.sh: OK (1112 tests)`. It reported 7.85 s there, but Swift Testing's per-test time includes the time a test waits for its turn before its body runs: the median test of that run reported 6.3 s, and `cancellingBeforeTheFirstByteCancelsTheRequest`, whose first wait is 5 s, reported 7.6 s. The 8 s wait itself was not close. As instructed, the test was left unchanged. If it fails again under a load like step 5b's (52, three agents building), the fix that keeps what it checks: wait up to a minute for the first deltas (the condition unchanged), make the stub stream long enough that it cannot end by itself during any wait, and check promptness as "no more than the delta already on its way reaches the consumer after the cancel" rather than "within 3 s".

**Later, after the rename (coordinator).** The coordinator's final run on `main`, started right after a build (load 12–17), failed four timing tests at once, all about 12 s into the run: this one, `StubURLProtocolTests.cancellingTheConsumerStopsADelayedDelivery`, `CLITimeoutTests.aProbeThatHangsIsKilled` and `CLIResolverTests.brokenCandidatesAreSkipped`. All four passed in the two runs that followed. The cause is the same in each: with 1,200 tests in one process, a test's own task can wait seconds for a thread, and each test measured its deadline on the wall clock. Fixed in the tests only, keeping what each checks: the two stub streams are 2,000 chunks (100 s if left alone, so they cannot end during a wait); `eventually` limits are 30–60 s (they return as soon as the condition holds); and each wall-clock bound is 30 s, far under the failure it guards against: the 100-second body, the 60-second retry wait, the hung fake's 600-second sleep. The full suite then passed after a build, on a quiet machine, and with ten busy loops on the eight cores (load rising to 44): `test.sh: OK (1200 tests)` each time.
